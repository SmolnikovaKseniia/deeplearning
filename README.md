# ЛР1. Реалізація та перевірка зворотного поширення похибки

Відтворення (Python 3.12, `uv`):

```
uv run python main.py        # правильна реалізація
uv run python main.py --bug  # дослід без ділення на N
```

Дані: Iris, стратифікований поділ 35/15 на клас (`default_rng(0)`), стандартизація за train (`ddof=0`). Мережа Linear(4, 8) → ReLU → Linear(8, 3), усе у float64. Кількість параметрів: 4·8 + 8 + 8·3 + 3 = 67.

## Прямий прохід

Рядкова конвенція, N = 105, K = 3.

| Масив | Формула                | Форма  |
| ----- | ---------------------- | ------ |
| X     | стандартизовані ознаки | (N, 4) |
| z1    | X W1 + b1              | (N, 8) |
| a1    | max(z1, 0)             | (N, 8) |
| z2    | a1 W2 + b2             | (N, 3) |
| q     | softmax(z2)            | (N, 3) |

Втрата: `L = −(1/N) Σᵢ log q[i, yᵢ]`, `log q = s − log Σⱼ exp(sⱼ)`, `s = z2 − max_j z2`

Збережені для backward: `X, z1, a1, q, y`. `X` потрібен для dW1, `a1` — для dW2, `z1` — для маски ReLU, `q` — для dz2.

Чому log-softmax зі зсувом: наївний `exp(z)/Σexp(z)` переповнюється вже при z ≈ 89 у float32 (лекція 1), а тотожність `log Σ exp(zⱼ) = m + log Σ exp(zⱼ − m)` з `m = max z` точна й безпечна, бо всі показники ≤ 0. Для one-hot мітки крос-ентропія дорівнює −log q_y, тобто це NLL, і ми мінімізуємо те саме, що максимізує MLE.

Пам'ять: кеш активацій має розмір Θ(N·Σnₗ) і росте лінійно з N, параметри в нього не входять.

Щоб не потрапити в пастку broadcasting `(N, 1) − (N,) → (N, N)`, у `forward` стоять `assert` на форми `y`, `z1`, `z2`, а в `backward` — на збіг форм градієнтів і параметрів.

## Зворотний прохід

Y — one-hot, ∂L/∂z2 = (q − Y)/N (∂L/∂z = q − y).

| Градієнт | Формула         | Форма  |
| -------- | --------------- | ------ |
| dz2      | (q − Y)/N       | (N, 3) |
| dW2      | a1ᵀ dz2         | (8, 3) |
| db2      | Σᵢ dz2[i]       | (3,)   |
| da1      | dz2 W2ᵀ         | (N, 8) |
| dz1      | da1 ⊙ 1[z1 > 0] | (N, 8) |
| dW1      | Xᵀ dz1          | (4, 8) |
| db1      | Σᵢ dz1[i]       | (8,)   |

Маска `1[z1 > 0]` — діагональний якобіан ReLU, `diag(φ′(z))`.

### Звідки беруться формули

1. **dz2.** Для одного прикладу L = −z_y + log Σⱼ exp(zⱼ), тому ∂L/∂zₖ = qₖ − 1[k = y], тобто q − y. Втрата усереднюється за N, звідси множник 1/N.
2. **dW2, db2.** z2 = a1 W2 + b2, тому z2[i, k] = Σⱼ a1[i, j] W2[j, k] + b2[k]. Похідна за W2[j, k] — це Σᵢ a1[i, j] dz2[i, k], тобто a1ᵀ dz2. Зсув b2 додається до всіх рядків, тож його градієнт — сума dz2 за прикладами.
3. **da1.** a1[i, j] входить у z2[i, k] з вагою W2[j, k], тому da1[i, j] = Σₖ dz2[i, k] W2[j, k], тобто dz2 W2ᵀ.
4. **dz1.** a1 = ReLU(z1) поелементно, якобіан діагональний, і похідна ReLU дорівнює 1 при z > 0 та 0 при z < 0. У нулі класичної похідної немає, ми беремо 0, як і PyTorch (`z1 > 0` у коді).
5. **dW1, db1.** Ті самі міркування, що в п. 2, але з X замість a1.

У термінах лекції 1: backward — це добуток якобіанів справа наліво, ∂L/∂z2 · J₂ · J₁ ..., де ми завжди множимо вектор-рядок на матрицю (VJP) і не будуємо повних якобіанів. Для скалярної втрати це reverse mode, що коштує O(Ln²) замість O(Ln³).

## Дослід із помилкою

Прогноз (записаний до запуску `--bug`):

- Втрата не зміниться: помилка лише в backward, `forward` не змінювався.
- Усі ненульові градієнти зростуть рівно в N = 105 разів, бо dz2 множиться на N, а решта формул лінійні за dz2.
- Звірка градієнтів з PyTorch та чисельна перевірка мають провалитися. Звірка втрат проходить. Чисельна похідна рахується від незміненої втрати, тому дає правильне значення.

## Висновки

- Ручний backward збігається з PyTorch autograd з точністю ~1e-16 і з чисельною похідною з точністю ~1e-10 (центральна різниця має похибку O(ε²) плюс округлення).
- Збіг втрати нічого не каже про правильність градієнтів: у досліді втрата збіглася, а всі градієнти були завищені в N разів.
- Autograd перевіряє всі елементи градієнтів одразу, але це лише порівняння з іншою реалізацією. Чисельна похідна незалежна від обох, зате вимагає двох прямих проходів на кожен параметр, тому використовується вибірково (чотири елементи).
- Якби в версії з багом оновлювали ваги, це було б еквівалентно кроку з lr, більшим у N разів, тому така помилка могла б проявитися лише як нестабільне навчання.
